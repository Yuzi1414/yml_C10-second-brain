# debug-workflow

## What
一条「按根因修 bug」的流程。核心价值：先复现、先定位唯一根因，再动手，否则会打地鼠。

## When to Use
- 运行报错（脚本、CLI、API 调用失败）。
- 现象是「某个字段/结构/键名对不上」之类的问题。

## Input
- 复现命令 + 完整报错信息。
- 相关源码/接口文档（若有）。

## Steps
1. 稳定复现：用最小命令复现报错，确认不是偶发。
2. 读源码/文档定位根因：找到「唯一」出错点（字段名、结构、参数）。
3. 单点修复：只改根因处，不顺手改无关代码。
4. 回归验证：重跑，确认报错消失且相关路径不受影响。
5. 记录：把「根因 + 修复」写进 AI 日志/AAR，沉淀成经验。

## Tools
- bash（复现）、read_file/grep（读源码）、edit_file（修复）。

## Output
- 修复后的可运行代码 + 一条根因记录（进 L2 经验）。

## 使用与迭代记录
- 使用次数：3（C9 KeyError「acc vs accuracy」；C10 runtime payload「challengeId 必填」；C6 脚本路径坑）。
- 迭代 v1→v2：v1 见报错先改代码；v2 加「先复现 + 定位唯一根因」步骤，C9/C10 两次都一击命中。
- 淘汰标记：无。

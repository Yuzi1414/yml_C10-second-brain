# version-management

## What
一条「让文件可追溯、可回退」的制度化流程。核心价值：命名/目录/权限/版本记录四件套，缺一不可。

## When to Use
- 项目文件多、多人/多轮协作、有「改错想回退」的需求。
- 需要交付「版本管理规范」类成果（如 C6）。

## Input
- 项目目录现状 + 协作平台（本地 Git / 飞书 / 网盘）。

## Steps
1. 命名规则：统一前缀（如 yml_C6_*）+ 禁止文件名清单（空格/特殊字符）。
2. 目录规范：按阶段/模块分目录，不散放。
3. 权限矩阵：谁能读/改/删，速查表化。
4. 版本记录表：每次改动留痕（谁、何时、改了什么、为什么）。
5. 回退演练：真做一次回退（Git 回滚 / 飞书历史版本），留截图证据。

## Tools
- Git / 飞书历史版本、write_file、bash。

## Output
- 规则文档 + 权限矩阵 + 版本记录表 + 回退测试证据。

## 使用与迭代记录
- 使用次数：2（C6 模板；C8 仓库 push 前目录梳理）。
- 迭代 v1→v2：v1 只有规则文档；v2 补「回退演练证据」，从「制度」补到「验证」。
- 淘汰标记：无。
